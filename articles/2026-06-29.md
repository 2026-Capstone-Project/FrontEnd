### 2. [Bugfix] 임시 일정/할 일 삭제 및 수정 시 서버 요청 방지 (Merge pull request #126)
**작성자: Yeonjin Kim**

#### [문제 상황 분석]
사용자가 캘린더에서 드래그나 클릭을 통해 임시 일정을 생성한 직후, 이 일정이 서버에 저장(Persist)되기 전에 수정하거나 삭제를 시도할 때 클라이언트가 서버로 `PATCH` 또는 `DELETE` 요청을 보내는 문제가 있었습니다. 이는 서버 에러를 유발할 뿐만 아니라 불필요한 네트워크 트래픽을 발생시켰습니다.

#### [해결 방안 및 기술적 분석]
1. **임시 상태 플래그(`isTemporary`) 도입**: 
   `CalendarEvent` 타입에 `isTemporary?: boolean` 속성을 추가하여, 현재 이벤트가 클라이언트 측의 임시 드래프트 상태인지 서버에 등록된 상태인지를 명확히 구분했습니다.
   
2. **이벤트 ID 업데이트 로직 최적화**: 
   서버로부터 성공적으로 데이터를 생성했다는 응답을 받으면, 임시 ID를 실제 서버 ID로 교체함과 동시에 `isTemporary` 플래그를 `false`로 전환하도록 `useCalendarEvents` 훅을 보완했습니다.

3. **API 요청 조건부 차단**: 
   `useSchedulePatch`, `useTodoFooter`, `useTodoEditorForm` 등에서 데이터 수정/삭제 요청을 보내기 전, `initialEvent?.isTemporary` 혹은 `isPersistedTodoId` 검증을 거쳐 임시 데이터일 경우 API 호출 없이 `Promise.resolve()`를 반환하거나 조기 리턴(`return`) 처리하도록 방어 코드를 작성했습니다.

4. **웹 접근성(A11y) 및 스타일 보완**:
   `TodoCard` 내의 삭제 아이콘(`Trash`)을 단순 클릭 이벤트 바인딩 대신, 의미론적(Semantic) 마크업인 `<button type="button">`으로 감싸고 `aria-label`을 부여하여 스크린 리더 지원 등 웹 접근성을 개선했습니다.
