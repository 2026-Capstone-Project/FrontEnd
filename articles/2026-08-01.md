# [2026년 08월 01일] 웹 성능·SEO 대폭 개선 및 캘린더 라이브러리 경량화 완료

오늘 팀 **Calio**는 프론트엔드 웹 서비스의 성능 최적화, 검색엔진 최적화(SEO), 그리고 배포 안정성 확보에 집중했습니다. 무거운 날짜 처리 라이브러리인 `moment.js`를 `dayjs`로 전면 교체하여 번들 용량을 크게 축소하였으며, 빌드 타임 라우트별 프리렌더(Prerender) 시스템 도입 및 Lighthouse CI 연동을 통해 SEO 및 초기 로딩 성능을 대폭 개선했습니다. 또한, 배포 직후 발생할 수 있는 lazy 청크 로드 실패 이슈를 방지하는 복구 로직을 구현하여 main 브랜치 배포까지 성공적으로 마쳤습니다.

#### 1. 날짜 라이브러리 전환 (`moment.js` ➔ `dayjs`)
* **기술 분석**: 기존의 무거운 `moment` 라이브러리를 제거하고 `dayjs`로 전환했습니다. react-big-calendar의 localizer 역시 `dayjsLocalizer`로 교체되었으며, `isBetween`, `isSameOrAfter`, `isSameOrBefore` 등의 플러그인과 한국어 로케일(`ko`)을 전역 모듈(`src/shared/utils/dayjs.ts`)에서 일괄 관리하도록 구성했습니다.
* **성과**: `CalendarPage` 청크 용량이 **359kB에서 295kB(gzip 기준 113kB ➔ 92kB)**로 감소했습니다.

```typescript
// src/shared/utils/dayjs.ts
import 'dayjs/locale/ko'

import dayjs from 'dayjs'
import isBetween from 'dayjs/plugin/isBetween'
import isSameOrAfter from 'dayjs/plugin/isSameOrAfter'
import isSameOrBefore from 'dayjs/plugin/isSameOrBefore'

dayjs.locale('ko')
dayjs.extend(isBetween)
dayjs.extend(isSameOrAfter)
dayjs.extend(isSameOrBefore)

export default dayjs
```

#### 2. 빌드 타임 라우트별 프리렌더(Prerender) 도입 및 SEO 개선
* **기술 분석**: 별도의 복잡한 SSR 서버를 구축하지 않고 Vite의 `ssrLoadModule`을 활용하는 `scripts/prerender.mjs` 스크립트를 작성했습니다. 빌드 타임 시 정적 HTML을 정교하게 생성하여, JS 실행 능력이 없는 크롤러나 SNS 링크 미리보기 봇이 메타데이터와 첫 페이지 본문을 올바르게 수집할 수 있도록 개선했습니다.
* Emotion의 서버 사이드 스타일 추출(`@emotion/server`)을 적용하여 FOUC(Flash of Unstyled Content) 현상을 방지했습니다.
* 라우트 메타데이터를 `src/shared/seo/routeMeta.ts`에서 단일 소스로 관리하여 런타임(`PageMeta`)과 빌드 타임(프리렌더) 간 문구 불일치를 원천 차단했습니다.

```json
// package.json
{
  "scripts": {
    "dev": "vite",
    "build": "tsc -b && vite build && node scripts/prerender.mjs"
  }
}
```

```javascript
// infra/cloudfront-spa-router.js
/* CloudFront Function (viewer request) */
function handler(event) {
    var request = event.request;
    var uri = request.uri;

    // 라우트별 정적 HTML(/login -> /login/index.html) 서빙 재작성
    if (!uri.includes('.') && uri !== '/') {
        request.uri = uri + '/index.html';
    }
    return request;
}
```

#### 4. 배포 안정성 및 lazy 청크 로드 예외 복구 (Fix)
* **기술 분석**: 신규 배포 시 S3 `--delete` 옵션으로 인해 구버전 탭을 켜둔 사용자가 기존 해시 자산을 요청할 때 Chunk Load Error가 발생하는 문제를 방지하기 위해 `/assets` 경로 업로드 시 `--delete` 옵션을 제거했습니다.
* 라우터 최상위에 `errorElement`를 배치하고, 청크 로드 실패를 감지하면 30초 쿨다운 기간 내에서 1회 자동 페이지 재로딩을 실행하는 복구 구문을 추가했습니다.

```typescript
// src/pages/common/ErrorPage/ErrorPage.tsx (청크 로드 에러 감지 logic)
const isChunkLoadError = (error: unknown) => {
  const message = error instanceof Error ? error.message : ''
  return /dynamically imported module|Importing a module script failed/i.test(message)
}

useEffect(() => {
  if (isChunkLoadError(error)) {
    const lastReload = Number(sessionStorage.getItem(CHUNK_RELOAD_AT_KEY) || 0)
    if (Date.now() - lastReload > CHUNK_RELOAD_COOLDOWN_MS) {
      sessionStorage.setItem(CHUNK_RELOAD_AT_KEY, String(Date.now()))
      window.location.reload()
    }
  }
}, [error])
```
