# [2026년 10월 08일] 배포 파이프라인 수동 트리거(workflow_dispatch) 지원을 통한 운영 유연성 확보

오늘 우리 Calio 팀은 CI/CD 배포 파이프라인의 편의성과 안정성을 높이기 위한 인프라 설정을 개선했습니다. 기존에 `main` 브랜치 푸시 이벤트에만 의존하던 배포 트리거 방식을 보완하여, 관리자 및 엔지니어가 필요 시 즉각적으로 배포 작업을 실행할 수 있도록 워크플로우를 개선했습니다.

## 🌿 Branch: main

### 1. 배포 워크플로우 수동 실행 트리거 추가
- **작업자:** Yujin Ji

#### 기술 분석 및 리뷰
Yujin Ji 님께서 `.github/workflows/deploy.yml` 파일에 `workflow_dispatch` 이벤트를 추가했습니다.

기존 파이프라인은 `main` 브랜치에 코드가 머지되거나 푸시될 때만 자동 배포되도록 설정되어 있었습니다. 이러한 방식은 정상적인 개발 흐름에서는 이상적이지만, 배포 환경의 일시적 장애 복구, 캐시 갱신, 롤백 테스트 등 긴급히 재배포가 필요한 상황에서는 불필요한 빈 커밋(Empty commit)을 생성해야 하는 비효율이 존재했습니다.

이번에 추가된 `workflow_dispatch` 설정 덕분에 GitHub 웹 UI나 CLI(gh), REST API를 통해 언제든 원하는 시점에 수동으로 배포 작업을 트리거할 수 있게 되었습니다. 운영 상황에서의 기동성과 유연성을 크게 확보한 유의미한 개선입니다.

향후 필요에 따라 특정 배포 타깃(staging, production)을 지정하거나 환경 변수를 오버라이드할 수 있도록 `inputs` 옵션을 확장하는 방안도 검토해 볼 만합니다.
