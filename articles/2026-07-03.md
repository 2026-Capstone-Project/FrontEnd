### 2. 임시 이벤트(Draft Event) 상태 관리 체계 구축 (Critical Refactoring)
**작성자: Yujin Ji**

캘린더에서 드래그나 클릭을 통해 임시로 생성된 일정(Draft)이 서버에 생성(`POST`)되기 전에 수정(`PATCH`) 요청을 보내는 오작동을 방지하기 위해 `isTemporary` 플래그를 도입했습니다.

*   **동작 원리:** 
    1. 캘린더 페이지에서 일정을 새로 생성할 때 `isTemporary: true` 속성을 부여합니다.

    3. 일정 수정 훅(`useSchedulePatch`, `useTodoEditorForm`)에서는 해당 플래그를 검사하여 임시 이벤트인 경우 `PATCH` 요청을 원천 차단하고 `POST`로 흐름을 유도합니다.

## 📝 시니어 개발자 총평

오늘 작업은 서비스의 사용자 경험(UX)과 아키텍처 안정성 측면에서 매우 중요한 이정표입니다. 

1. **랜딩 페이지 도입**을 통해 제품의 정체성을 명확히 하고 신규 유저 유입 경로를 확보했습니다.
2. **`isTemporary` 플래그 도입**은 클라이언트 상태와 서버 데이터베이스 간의 싱크 불일치로 발생할 수 있는 잠재적 API 에러(존재하지 않는 ID에 대한 PATCH 요청)를 프론트엔드 레이어에서 우아하게 방어해 낸 훌륭한 리팩토링 사례입니다.
3. **웹 접근성(A11y) 개선** 또한 서비스 퀄리티를 높이는 중요한 디테일입니다.

다음 스프린트에서는 오늘 구축한 공유 일정 API를 기반으로 실시간 알림 피드백을 고도화하고, 랜딩 페이지 내 소셜 로그인 전환율을 추적할 수 있는 지표 분석 환경을 마련하도록 하겠습니다. 모두 수고하셨습니다.
