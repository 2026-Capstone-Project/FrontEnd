# [2026년 07월 06일] AI 채팅 접근성 개선 및 전반적인 아이콘 에셋·스타일 구조 리팩토링

오늘 우리 "Calio" 팀은 서비스의 완성도를 높이기 위해 사용자 경험(UX)과 직관적인 개발 환경(DX)을 모두 챙기는 내실 다지기 작업을 진행했습니다. 

주요 진행 상황으로는 최근 도입된 **AI 채팅 플로팅 버튼의 웹 접근성(A11y) 표준 준수 작업**과 **포커스 스타일 최적화**를 완료했습니다. 또한, 프로젝트 전반에 산재해 있던 **공통 아이콘 에셋들의 경로를 체계적으로 정리**하고, 친구 관리 화면의 **인라인 스타일들을 Emotion styled-components로 분리**하여 렌더링 성능과 코드 유지보수성을 크게 향상시켰습니다.

### 1. AI 채팅 버튼 접근성 개선 및 포커스 링 최적화
**작성자: Yeonjin Kim**

* **기술적 분석**: 
  스크린 리더 사용자 및 키보드 네비게이션 사용자를 위한 웹 접근성(A11y) 표준을 강화했습니다. 단순히 마우스 클릭만 고려하던 기존 플로팅 버튼에 `type="button"`, `aria-label`, `aria-expanded` 속성을 동적으로 부여하여 현재 AI 채팅창의 열림/닫힘 상태를 보조기기가 인지할 수 있도록 개선했습니다. 내부의 로봇 아이콘(SVG)에는 `aria-hidden="true"`와 `focusable="false"`를 선언해 스크린 리더가 불필요하게 아이콘을 이중으로 읽는 현상을 방지했습니다.
  또한, 마우스 클릭 시 발생하는 기본 아웃라인 포커스 링은 `&:focus { outline: none; }`으로 제거하되, 키보드 탭 키를 통해 진입했을 때만 명확한 시각적 피드백을 주도록 `&:focus-visible` 스타일을 정교하게 추가했습니다.

* **주요 코드 변경점**:

### 2. 친구 화면 인라인 스타일 분리 및 반응형 구조 개선
**작성자: Yeonjin Kim**

* **기술적 분석**: 
  `FriendItem`, `ScheduleItem`, `SharedScheduleItem` 등 친구 관리 도메인 내 컴포넌트들에 적용되어 있던 인라인 스타일(`style={{ ... }}`)을 Emotion styled-components 구조로 완전히 분리했습니다. 인라인 스타일은 매 렌더링마다 새로운 객체를 생성하여 가비지 컬렉션(GC) 부담을 늘리고 성능 저하의 원인이 되므로, 이를 전용 `.style.ts` 파일로 이관함으로써 컴포넌트의 가독성과 성능을 동시에 확보했습니다.
  더불어, 하드코딩되어 있던 미디어 쿼리 구문을 공통 미디어 유틸리티(`media.down`) 및 테마 변수(`theme.breakPoints.tablet`) 기반으로 전환하여 화면 크기에 따른 UI 대응력을 한층 강화했습니다. 사용하지 않는 모의 데이터 파일(`scheduleTodoData.ts`)도 함께 정리했습니다.

* **주요 코드 변경점**:
```typescript
// src/features/Friends/Friend.styles.ts
import styled from '@emotion/styled'
import { media } from '@/shared/styles/media'
import { theme } from '@/shared/styles/theme'

export const PageLayout = styled.div`
  display: flex;
  gap: 24px;
  /* ... 중략 ... */

  ${media.down('1040px')} {
    flex-direction: column;
    padding: 16px;
  }
`
```

### 4. 공통 아이콘 에셋 위치 이동 및 Import 경로 대대적 정리
**작성자: Yeonjin Kim**

* **기술적 분석**: 
  기존에 `@/shared/assets/icons/`와 `@/assets/icons/`에 중구난방으로 흩어져 있던 SVG 아이콘 파일들을 `@/assets/icons/common/` 및 `@/assets/social/` 경로로 명확히 분류하여 재배치했습니다. 
  이 과정에서 소셜 로그인 아이콘(`google`, `kakao`, `naver`)의 배경 유무에 따른 에셋 정리를 진행했으며, 실수로 누락되어 빌드 에러를 유발할 수 있었던 에셋들을 신속히 복원(`fix: 삭제된 svg 에셋 복원`)했습니다.
  이후 프로젝트 내의 모든 컴포넌트(토스트, 체크박스, 드롭다운, 모달, 데이트피커 등 약 20여 개 파일)의 import 경로를 일괄 업데이트하여 에셋 관리 체계를 단일화했습니다.

* **주요 코드 변경점**:
```typescript
// src/features/Auth/components/LoginCard/LoginCard.tsx
-import GoogleIcon from '@/assets/icons/google.svg?react'
-import KakaoIcon from '@/assets/icons/kakao.svg?react'
-import NaverIcon from '@/assets/icons/naver.svg?react'
+import GoogleIcon from '@/assets/social/google.svg?react'
+import KakaoIcon from '@/assets/social/kakao.svg?react'
+import NaverIcon from '@/assets/social/naver.svg?react'
```
```typescript
// src/shared/ui/Modals/ItemEditorModal/EditorModalLayout.tsx
-import Check from '@/shared/assets/icons/check.svg?react'
-import Close from '@/shared/assets/icons/close.svg?react'
-import Trash from '@/shared/assets/icons/trash-2.svg?react'
```

### 💡 시니어 개발자 총평
오늘 진행된 작업들은 겉으로 보이는 큰 기능 개발은 아니지만, 프로덕션 퀄리티의 서비스를 만들기 위해 반드시 거쳐야 하는 **웹 표준 준수**와 **코드 베이스 정형화** 작업이었습니다. 

특히, 플로팅 버튼의 키보드 접근성 대응은 소외되는 사용자 없이 모두가 Calio의 AI 기능을 편리하게 이용할 수 있도록 돕는 중요한 개선이었습니다. 또한 프로젝트 규모가 커짐에 따라 에셋 경로가 꼬이기 쉬운데, 이번 기회에 Yeonjin Kim 개발자가 아이콘 경로를 깔끔하게 단일화하고 인라인 스타일을 제거함으로써 향후 유지보수 속도가 크게 향상될 것으로 기대합니다. 

앞으로도 기능 구현 단계에서부터 스타일 분리와 접근성 마크업을 염두에 두고 개발할 수 있도록 팀 내 가이드를 지속적으로 고도화하겠습니다. 모두 고생하셨습니다.
